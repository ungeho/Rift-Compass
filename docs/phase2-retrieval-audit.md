## 1. 目的と方法

Phase 1 の評価に使った24問とは別に、初めて与える18問で、次を確かめました。

- 実際の疑問に対して、適切な資料が見つかるか
- 直接役立つ資料が1位・3位以内にあるか
- 検索結果が誤解を招いていないか
- 検索の失敗と資料不足を区別できるか
- 未検証の知識を、検証済みの事実として扱っていないか

**実行方法**：`src/search/phase2Audit.test.ts` が、18問を現行の `search()` にそのまま渡して結果を出力します。評価用の検索ロジックは持たず、合否も判定しません。

```
PRINT_AUDIT=1 npx vitest run src/search/phase2Audit.test.ts --silent=false
```

**「直接役立つ資料」の判定**：検索順位の一致と、資料が質問に答えられることを分けるため、次の2段階で判定しました。

- **確認済み（厳格）**：本文を取得して確認した資料（L3）か、その資料を根拠にした知識ノートが、質問の中心に答えている。
- **未確認の候補（緩い基準）**：L2 の動画で、チャプター名が質問とそのまま対応している。本編を見ていないため、内容が正しいかは保証しません。

L3 も「資料にそう書かれている」という意味で、現行パッチのゲーム内で検証したという意味ではありません。

## 5. 失敗原因の分析

1. **質問文に含まれる一般的な語が、必須条件になりすぎる（P04・P05、副次で P02・P12）**
   - Phase 1 のレビュー修正で、「具体的な語（資料の1/4以下に現れる語）はすべて必須」にしました。そのため、「レーン」「ミニオン」「説明」のような、質問文に自然に入る語まで必須になっています。
   - 結果、答えている資料が「一部の条件」と表示されます。順位そのものは良いので、主に表示の問題（PRESENTATION）として現れています。
2. **Topic の別名や Topic の付与が足りない（P03・P10、副次で P02）**
   - 「狙われる」「ボットレーン」に対応する別名がなく、Wiki Flash には「クールダウン」の Topic が付いていません。
   - P03 では、これに「除外した語＋語だけ→0件」の規則が重なりました。その結果、資料があるのに「該当なし」と表示されています。最も深刻な失敗です。
3. **収録範囲の不足（9問）**
   - オブジェクト（ドラゴン・ヘラルド・バロン）、ジャングルのキャンプ時間、テレポートの仕様、チャンピオンの対面別の情報（アーリ対ベイガー）、スキルの上げ順の一般論などを扱う資料がありません。
   - 検索側は、P13〜P15 を0件と正しく案内できています。一方、P16・P18 では関連の薄い候補が並びます。
4. **確認の深さ（P09・P11、副次で多数）**
   - L2 動画の中身や、現行パッチでの仕様は確認していません。画面は「本編未確認」「現在への適用：未確認」と表示しており、検証済みのようには見せていません。
5. **根拠資料のない知識ノートに到達できない（P07）**
   - ノートは「資料の詳細画面」からしか見えません。そのため、根拠資料のない仮説ノートは、データにあっても利用者に届きません。

## 6. 改善案の候補（3件に絞る）

### 案1：質問文中の「語」を必須条件から外し、加点に使う（検索コードの変更）

- **対象**：P04・P05（PRESENTATION）。副次で P02・P10・P12 の表示。
- **最小限の対応**：`search.ts` の `required` を、Topic と発信者の概念だけにします。語（term）は一致すれば加点するだけにします。Topic も発信者もない検索では、従来どおり語を必須にします。
- **期待できる改善**：P04・P05 の1位資料が「条件に一致」になる見込みです。ただし、この試算は検索を書き換えて実測したものではなく、**未検証** です。
- **変更ファイル**：`src/search/search.ts`、`src/search/search.test.ts`、`src/components/display.test.tsx`、`docs/retrieval-evaluation.md`
- **リスク**：「VeigarV2 ダメージ計算」のような未知語の扱いには影響しません（未知語は別の判定です）。一方、Q09（AA無効化＋スキル）などで full の件数が増え、「条件に一致」が緩くなります。24問の再評価が必要です。
- **作業コスト（見積もり）**：実装とテストで1〜2時間、24問と18問の再評価で1時間程度。

### 案2：Topic の別名・Topic の付与・紹介文の小さな修正（データの変更のみ）

- **対象**：P03（SEARCH、最重要）、P10（SEARCH）、P02（副次）、P16（副次）
- **最小限の対応**（いずれも1〜数語の追加）：
  - Topic `minion-aggro` に別名「ミニオンに狙われる」「minion targeting」を追加。「狙われる」単独は、ガンクの文脈でも誤って一致するため避けます。
  - `res-wiki-flash` の `topic_ids` に `cooldown` を追加。
  - Topic `cat-laning` に「ボットレーン」「ボット」「bot lane」を追加。「ボット」単独は誤一致の確認が必要です。
  - `res-wiki-summoner-spell` の紹介文に、テレポート 420秒など全スペルの基本 CD を記載。
- **期待できる改善**：P03 が0件から到達できるようになり、P10 は Wiki Flash が「条件に一致」になる見込みです（未検証）。
- **変更ファイル**：`data/sample-resources.json` のみ（検証は `npm run test`）。
- **リスク**：別名の誤一致です。Phase 0 の24問と今回の18問で再評価すれば確認できます。データ正本の変更なので、確認レベルや根拠の状態は変えないようにします。
- **作業コスト（見積もり）**：30分〜1時間。**新しい外部資料の調査は不要** です。

### 案3：オブジェクトとサモナースペルの基本仕様の資料を少数追加（新規資料の調査）

- **対象**：COVERAGE のうち、仕様の資料で答えの手がかりが得られる P14（ドラゴンソウル）・P15（リフトヘラルド）・P16（テレポート）・P18（バロン）。P13 はキャンプの出現時間までなら答えられます。
- **最小限の対応**：LoL Wiki の該当ページ（ドラゴン、ドラゴンソウル、リフトヘラルド、バロン、テレポート、ジャングルのキャンプ）**5〜6件程度** を、L3 で確認して Resource として登録します。Topic も数件追加します。
- **期待できる改善**：仕様を問う質問（P14・P16、P15・P18 の仕様部分）に答えられるようになります。ただし、「いつ使うと最大化できるか」「どう判断するか」といった戦術の部分は、解説資料がないと答えられません。
- **変更ファイル**：`data/sample-resources.json`、`docs/source-research.md`
- **リスク**：仕様が頻繁に変わる領域なので、パッチ依存の管理が増えます。戦術の質問に、仕様ページが「答え」のように見える危険もあります。
- **作業コスト（見積もり）**：調査と登録で2〜4時間。戦術の解説資料まで集める場合は、その数倍かかります。

**優先順位の提案**：案2 → 案1 → 案3 の順です。案2はデータ数語で最も深刻な P03 を直せます。案1は表示の過小評価を広く直せますが、24問の再評価が必要です。案3は外部資料の調査を伴うため、P13〜P18 のような質問が実際の利用者から来るか確かめてからでよいと考えます。

## 7. 評価の限界

- **質問の出どころ**：18問は、ChatGPT が作った新規の評価質問です。実際の利用者から集めたものではありません。表現の分布（「〜したい」「〜の方がいい？」など）が、実際の利用者と違う可能性があります。
- **評価者の判断**：「直接役立つ資料か」の判定は評価者（AI）の判断です。とくに次の点には不確実性があります。
  - P02 の1位（経験値表）を「直接」に数えていません。
  - P09 を「直接の回答資料なし」に分類しました。
  - P11・P05 の L2 動画を「未確認の候補」としました。
- **確認の深さ**：判定に使った資料の内容は、Phase 0 の L3 確認（AIの要約経由）とデータ中の紹介文です。今回、資料を再取得したり動画を視聴したりはしていません。
- **母数の小ささ**：直接役立つ資料がある質問は6〜8問と少なく、Top1・Top3 の比率は大きく揺れます。
- **改善案の効果**：案1〜3の効果は、検索とデータを変更せずに見積もったもので、実測していません。
- **画面の確認**：画面上の表示（注意書きや区分）は、Phase 1 のテストとコードから判断しました。今回、ブラウザで目視はしていません。
