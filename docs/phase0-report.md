## 4. 軽量モデルで十分だった部分

- **資料を見つける用途の大半**。タイトル・発信者・Topic・日本語紹介文・別名で、24問中23問の期待資料に（机上照合で）到達できました。残る1問は、該当資料が存在しないことを確認するための質問です。
- **動画の区間への案内**。`segments` だけで、Note がなくても「どこを見ればよいか」に答えられます。
- **歴史の参照**。Season One や V3.14 などは、Resource だけで足ります。
- **翻訳の追跡**。`derived_from` だけで、原典と時期を区別できます。

## 9. 推奨案：次に実装すべき最小機能

1. **データの読み込みと検査**：`sample-resources.json` 相当のデータを読み込み、`tools/validate-sample-data.js` の検査（参照切れ、status の規則、`last_checked_patch` の規則）を、テストとして常に実行する。
2. **方式Bの検索**：タイトル・Topic・別名・日本語紹介文の検索と、言語・時期（era）・確認レベルの絞り込み。通常の推奨対象は、無料アクセスを確認した資料（`access.free: true`、L2以上）に限る。L0 の資料は調査候補として保存するだけにし、公開UIでは推奨しない。
3. **Resource 詳細の表示**：確認レベル、時期、翻訳の原典、動画の区間リンク（`&t=秒`）。L0〜L2 であることを目立つように表示する。
4. **Note の根拠状態の表示**：「資料に記載（L3）」「計算」「推論」「経験則」「未検証」と、ゲーム内検証の有無（Phase 0 時点ではすべて「未検証」）。古い主張には「対象時期」と「現在の適用可能性：未確認」を表示する。
5. **（その次）パッチ再確認リスト**：変更キーを入力すると、該当する Note を一覧にする。
6. **再現可能な検索評価**：方式Bの検索の実装と同じコードで、固定の質問セットに対する順位評価をテストとして用意する（`tools/desk-retrieval-check.js` の置き換え）。

いずれも、外部APIの自動取得やAIによる自動の要約は含めません（確認レベルの意味が崩れるため）。

アプリの実装時は、README に記載したローカル開発方針（`npm run dev` だけで起動、scripts の集約、日本語のセットアップ手順、起動時に再インストールやDB変更をしない）に従います。
