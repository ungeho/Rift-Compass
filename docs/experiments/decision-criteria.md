### A. トレード前の5指標と「2〜3個」（MetaBot）

- 原典の確認箇所：「How to trade in lane: the five-advantage checklist」の冒頭。
- 原典の言い方は「5つすべてが要ることはまれで、2つか3つが重なれば、通常は（usually）体力の有利を持って離れるのに十分」。
- 確かめたこと：
  - 目安の目的は「体力の有利」で、キルの基準ではない。
  - 「通常は」と書かれていて、必ずではない。
  - 5つの中身は、ミニオンアグロ、相手のスキルの CD、レベル、サモナースペル、持久力（回復とアイテム）。
  - 同じ節に「相手が主要スキルを無駄にした後の6〜8秒」がある。
- 比較できる独立した資料は見つからなかった。この目安は1つの出典だけのもの。

### B. フリーズで残すミニオンの数

原典を読み直すと、4つの資料（5か所）で、数えるものも状況も違っていた。

| 資料 | 原典の記述（要旨）| 数えるもの | 状況 |
|---|---|---|---|
| Dignitas（Ahrivve、2019年）「When to Recall」| キャスター2〜3体を残す | 残っているキャスターの数 | 押し切るのが間に合わず、安全に帰るために止めるとき |
| Dignitas（Chillwang、古い記事）| 満タンのキャスター3体以上が自分に向かって押している状態。自軍の各ウェーブが近接3・キャスター6以上と戦う | 残っている（押してくる）キャスターの数 | タワーの近く（隣ではない）で保つとき |
| LoL Theory（Griffin Wood）「How to Freeze a Lane」| 敵キャスターを3〜4体多く、タワーの射程のすぐ外で | 敵キャスターが自軍より多い数 | 15分より前。レート帯で効き方が違う（ダイヤ以上は1〜2CS を奪う程度に短く）|
| lol-guide（がりある）ウェーブの勘違い「3.」| 敵ミニオンを自軍より3〜4体多く残し続ける | 敵ミニオン（種類を問わない）の差 | 自陣側で保つとき |
| lol-guide（がりある）ウェーブを使った有利「2.」| 敵ミニオンが自陣ミニオンより3〜4体多い状態を維持 | 同上 | 不利時に、相手に押させて自陣タワーの手前で作るとき |

- Phase 5B の判断材料（du-freeze-when-behind-dignitas）は、2019年の「2〜3体」を、不利時のフリーズの手順として要約していた。原典の「2〜3体」は、「When to Recall」の節にある「帰る前に止める」話。最終確認で、判断材料そのものを原典に合わせて訂正した（§8）。目安は、本来の前提（帰るとき）とともに、判断材料に付けない独立した目安として記録した。
- 「キャスターが3体以上残る」と「3〜4体多い」が、同じウェーブの状態を指すかは、原典からは決められない。平均も統一もしない。

## 3. 具体的な目安の記録（16件）

各目安は、次の項目を必ず持つ（検査で確かめる）。

| 項目 | 内容 |
|---|---|
| about_ja | 何についての目安か |
| value_ja | 数値・単位（原典の言い方のまま）|
| target_ja | 何を数えるか、誰に当てはまるか |
| observe_ja | どう観測するか |
| context_ja | 成立する状況・前提 |
| source / locator | 出典と確認箇所 |
| basis | 原典の記述か、AI の整理か |

例：

| 目安 | 数値 | 前提 |
|---|---|---|
| トレードを仕掛けてよいか（MetaBot）| 5つの有利のうち2〜3つ | 体力の有利が目的、「通常は」|
| 相手が主要スキルを使った後の攻め時（MetaBot）| 6〜8秒 | スキルが戻るまで |
| 押し込めていないときのリコール（lol-guide）| 体力・マナが半分を切った段階 | 「状況にもよりますが」という前置き |
| オブジェクト前のリコール（lol-guide）| 出現の約1分半前（例：8分のヴォイドグラブ）| テレポートがあれば遅めでもよい |
| 敵ジャングラーの狩ったキャンプ数（lol-guide）| CS÷4（1キャンプ＝4CS）| 序盤の1周目 |
| 2周目の予測（lol-guide）| バフ5分、ほか2分15秒で再出現 | 2025年時点の仕様 |
| 序盤の合流（lolgaren）| 3:30 のスカトル。ジャングラーはレベル4で着けるか | 2024年の記事 |
| ボットのレベル2（lol-guide）| 6体＋前衛3体 | 2人で経験値を分けるレーン |

- 判断材料に付かない目安（unit_id が null）は4件。lol-guide のフリーズ2件、Dignitas 2019 の帰る前のフリーズ1件（§8 の訂正で判断材料から切り離した）、ソロレーンのレベル2の記述1件で、比較のためだけに記録した。

## 4. 資料間の比較（3組）

| 比較 | 判定 | 要点 |
|---|---|---|
| フリーズで残す敵ミニオンの数（5か所、4つの資料）| 条件や数え方が違い、直接は比較できない（同じ条件で矛盾しないかは未確認）| 「残る数」と「多い数」、「帰るとき」と「保つとき」と「作るとき」で違う。同じ状態を指すかは判断できない |
| リコールの判断基準（4か所）| 条件や数え方が違い、直接は比較できない（同じ条件で矛盾しないかは未確認）| 見る観測項目（ウェーブの番号、体力・マナ、時刻、押し切れるか）と時期が違う。「押し込んでから帰る」は共通 |
| レベル2になるミニオンの数（2か所＋正式データの知識ノート）| 矛盾かどうか判断できない | ボットの9体は知識ノートと一致。ソロの記述は文字どおり9体と読むと知識ノートの7体と合わないが、「全て倒すと先行できる」という十分条件の書き方で、必要数を述べてはいない |

- 判定（verdict）は AI の整理で、画面にもそう表示する。
- 同じ条件での矛盾（conflict）と判定した比較はない。無理に矛盾として扱っていない。
- lol-guide の2記事どうしは同じ著者で、独立した裏付けとは数えない（比較の「判断できない点」に明記）。
- 比較に入れたものの、判断材料として試験表示していない目安（ボットのレベル2など）は、目安だけを出し、判断材料へのリンクは作らない。

## 6. 評価

| 観点 | 結果 |
|---|---|
| 抽象的な原則が、観測できる基準として理解しやすくなったか | 一部で、なった。「トレードは有利なときに」が「5つのうち2〜3つ（体力の有利が目的）」に、「敵ジャングラーを追う」が「CS÷4 とバフの色」になった。ただし数値の目安を持つ判断材料は、38件中9件だけ |
| 数値とその前提を一緒に確認できるか | できる。目安は前提・対象・見る方法を必ず持ち（検査で確認）、画面でも同じ枠に出す（テストで確認）|
| 資料間の差異を失わずに比較できるか | できる。数値は原典の言い方のまま並べ、平均・統一・削除をしていない（テストで確認）|
| 異なる条件の数値を誤って矛盾扱いしていないか | していない。3組のうち2組は「条件が違い、直接は比較できない」、1組は「判断できない」で、「矛盾」は0組。逆に「矛盾しない」とも断定していない（同じ条件にそろえた比較は、原典からはできない）|
| 原典の主張と AI の推論を区別できるか | できる。目安は原典の記述か AI の整理かを持ち、比較の判定には「AI の整理」と表示する。ただし目安の文の中にも AI の補足（「計9体は AI が数えたもの」など）があり、文の中で書き分けている |
| 既存の判断材料9件の表示品質を損なっていないか | 損なっていない。Phase 5D の表示テストは、前提（件数9→14、参照するデータ）を直したうえで、すべて通る |
| 既存の資料検索84問の結果を維持できているか | 維持できている。変化0件 |

### 気づいた問題・限界

- **Phase 5B の要約と原典の文脈のずれ**：du-freeze-when-behind-dignitas は、2019年の記事の「2〜3体」を不利時のフリーズの手順として書いていた。原典ではリコール前の話だった。最終確認で判断材料を訂正した（§8）。
- **著者の偏り**：目安16件のうち8件、新しい判断材料9件のうち5件が、がりある（lol-guide）の記事。比較の中でも、lol-guide の2か所は同じ著者。
- **「判断できない」が残る**：フリーズの数の同等性、レベル2のソロの記述の意図は、原典からは決められなかった。
- **数値の現行での正しさ**：どの数値も、ゲーム内でも現行パッチでも確かめていない（ヴォイドグラブ8分、再出現タイマー、3:30 のスカトルなど）。
- **JS のサイズ**：442KB → 486KB（gzip で 128KB → 138KB）。実験データを2つとも読み込むため。

## 8. 最終確認での訂正（原典の確認による）

### du-freeze-when-behind-dignitas（Phase 5B の判断材料）

原典：Dignitas「A Guide to Improving Your Wave Management in League of Legends」（Ahrivve、2019-07-14）。Phase 5B と Phase 5E で確認した URL は同じ。

| 原典の節 | 書かれていること（要旨）|
|---|---|
| When to Recall | 帰る前は速く押すのが最善。押し切るのが間に合わなければウェーブを止め、少しの CS を失っても安全に帰る。止めるには「キャスターミニオンを2〜3体残す」 |
| When to Freeze, Why you Freeze Waves and How to Break Them | ガンクを繰り返し受けるとき、不利な対面で CS 差が30あるときに、自陣タワーの近くでフリーズして追いつく。相手はロームできるので、ワードと味方への連絡で備える。タワーにウェーブを撃たせると押し返される。**残すミニオンの数は書いていない** |

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 行動（action_ja）| 敵キャスターミニオンを2〜3体残してフリーズを作る（2019年の記事）。古い Dignitas の記事は、満タンのキャスターを3体以上残すとする | 自陣タワーの近く（タワーがミニオンを撃たない位置）でフリーズを作り、安全にファームする。2019年の記事のこの節は、残すミニオンの数を書いていない。古い Dignitas の記事は、タワーの近くで保つときに、満タンの敵キャスター3体以上が自分に向かって押してくる状態を保つとする |
| 未確認事項 | 残すミニオンの数は資料ごとに違う（2〜3体、3体以上、3〜4体多く）| 不利時のフリーズで残す数は該当節に書かれていない。「2〜3体」は帰る前に止める場面（When to Recall）の記述で、この判断の手順ではない |
| 確認箇所（2019年の記事）| When to Recall／When to Freeze… | When to Freeze…（この判断の根拠になる節だけ）|
| 関係の説明（Phase 5A の E3 との関係）| 残す数：Dignitas 2019 は2〜3体… | 資料ごとに数え方と場面が違い、Dignitas 2019 の2〜3体は帰る前の場面であることを明記 |

- 訂正の理由：Phase 5B では、同じ記事の2つの節を合わせて要約し、「帰る前に止める」場面の数値を、「不利時にフリーズする」手順の数値として書いていた。原典の該当節を読み直して確かめた。
- 残したもの：要旨（不利で CS 差があるときに、自陣タワーの近くでフリーズする）、理由、代償、壊し方は、「When to Freeze」の節に独立した根拠があるので、変えていない。古い Dignitas の記事（タワー近くで保つときの満タンのキャスター3体以上）も、その記事の文脈どおりなので残した。
- 目安：Phase 5E で作った「キャスター2〜3体を残す」（crit-freeze-digwave-recall）は、この判断材料から切り離した（unit_id を null）。比較（フリーズの数、リコールの判断基準）の中で、本来の場面とともに表示する。
- Phase 5B・5C の記録への注記：
  - Phase 5C の回答候補（decision-retrieval.md の Q13）に、この数値が場面なしで書かれていたため、訂正の注記を加えた。
  - Phase 5B の報告（decision-extraction.md）にも、訂正の注記を加えた。
  - 本文の記述そのものは、実験の記録として残している。
- Phase 5C の質問セット（Q13 の期待値の説明「資料ごとに数が違う」）は、訂正後も正しいので変えていない。

### 比較の表現

- 判定 different_conditions の表示を「矛盾ではなく、条件や数え方が違う」から「条件や数え方が違い、直接は比較できない（同じ条件で矛盾しないかは未確認）」に改めた。
- フリーズとリコールの比較の判定文も、「矛盾ではない」と断定しない表現に改めた。条件が違うので直接比べられないことと、同じ条件で矛盾しないと確かめたことは別で、原典からは後者を確かめられないため。

### 古い数値の表示

- 確認の結果、目安の枠には出典と確認箇所はあったが、資料の公開日が出ていなかった。比較の中で、2019年の記事と2026年の記事の数値が並んでも、時期が分からなかった。
- 次の3点を、既存の表示の中に加えた。
  - 目安の枠に、出典の公開日（実験データに記録したもの。未確認のものは「未確認」）を表示する。
  - 比較の節と、目安の節の注意書きに、「数値は資料の公開時期のもので、現行パッチでは確認しておらず、ゲーム内でも検証していない」と書いた。
  - 一覧のカードの数値に、「時期と前提は詳細で確認」と添えた。
- 現行パッチの仕様は補っていない。
