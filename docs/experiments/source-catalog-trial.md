## 7. 今後の運用案（省コストの繰り返し）

1. 週に1回など、`node tools/candidates/collect.js collect` を流す。既知の URL は取り直さないので、増えた分だけ取得する。
2. `report` の段階の内訳と「深い確認の順番待ち」から、数件ずつ本文を確認して `reviews.json` に書く。
3. 1原典から複数の知識を、節ごとに「著者の主張・仕様・AI の整理」に分けて収録記録に残す。正式資料にするか、判断材料にするかは別に決める（発掘数を判断材料の数で制限しない）。
4. 重複は捨てずに、既存の資料・判断材料との関係（同じ方向・追加の例外・異なる見解・同じ著者）を書く。
5. 自動取得できないサイト（Onetricks.gg・MobaFire・Mobalytics）は、回避せず、利用者が見つけた個別の URL を手で追加するか、ブラウザで個別に確認する。
6. YouTube は、チャンネル・再生リストのページと動画ページのメタデータまでにとどめ、字幕の本文・動画は取得しない。全件の一覧が要るなら Data API のキーを用意する。

### 原典を選ぶときの多様性

既存の優先区分（P1-common・P1-mid・P2・P3）は、MID とロール共通を優先していた時期の分類で、全ロール・全チャンピオンを集めるときは偏りを生む。収集方針は、全ロール・全チャンピオン・全マッチアップ・全言語と地域を対等な対象とするように更新された（2026-11-01）。この試行では優先区分の仕組みを変えておらず、次の作業で既存の分類処理を最小限変えて偏りを解消する。それまでの原典の選定では、ロール・チャンピオン・言語・著者の多様性も考え、特定のロール・チャンピオンに属することを保留の理由にしない。
