## 2. 判断の部品（29件）

### 形式

KnowledgeNote（`kind: "decision"` か `"principle"`）と Evidence に対応する形で記録した。

| 項目 | KnowledgeNote・Evidence との対応 |
|---|---|
| statement_ja / topic_ids / kind | KnowledgeNote の同名の項目 |
| conditions_ja / exceptions_ja | KnowledgeNote の同名の項目 |
| proposed_status | KnowledgeNote の status の案。解説者の主張なので、どれも `empirical`（解説者の経験則・主張）とした。L3 の `empirical_claim` Evidence に対応する |
| evidence（source, locator, evidence_type, checked_level）| Evidence の resource_id・locator・evidence_type・checked_level |
| problem / observations / goal / action / alternatives / costs | KnowledgeNote にはない、判断の部品のための項目 |
| reasons[].basis | `source`（原典が明示）か `ai`（AI の解釈）|
| scope / patch_dependency_ja / unknowns_ja | 対象ロール・チャンピオン・対面、パッチへの依存、未確認事項 |
| relations | 他の部品との関係（§4）|

### 原典から確認できなかった項目（29件中）

「原典に記載がない」と「読んでいないので分からない」を分けた。出典の全体を読んだ部品は「記載なし（全体を確認）」、未読の範囲がある出典の部品は「確認範囲に記載なし（未読の範囲あり）」と書く。検査スクリプトが、「不明」とだけ書くことと、未読の範囲がある出典で「記載なし」とすることを拒否する。

| 項目 | 記載なし（全体を確認）| 確認範囲に記載なし（未読の範囲あり）|
|---|---|---|
| 代償・リスク | 6 | 10 |
| 例外 | 6 | 13 |
| 代替選択肢 | 4 | 6 |
| 成立条件 | 1 | 4 |

- 全体を確認した出典だけで作った部品（9件）でも、代償6件・例外6件は記載がなかった。原典は「何をするか」と「なぜか」はよく書くが、**代償と例外はあまり書かない**傾向がある。
- 未読の範囲がある部品の「記載なし」は、読めば見つかる可能性がある。原典にないとは言えない。
- 一般知識で埋めず、そのまま残した。
- 代償を AI が補った箇所（例：ロームを追わないと味方を助けられない）は、「AI の解釈」と書き分けた。
- 理由に AI の解釈を含む部品は1件だけ（ブラッドミアの2記事を並べた比較）。

### 単なる要約より役立つか

- 役立つと判断した。資料の要約（Resource の summary_ja）は「何が書いてあるか」を述べる。判断の部品は「どんな状況で、何を見て、何を選び、なぜか、いつ成り立たないか」に分けている。そのため、別の資料の同じ判断と並べて比べられる（§4）。
- 例：「ロームを追わない」は、lol-guide では待ち伏せと移動時間が理由で、追ってよい条件がある。Dopa では TF の R があるので追う。LoL Theory では、相手が踏み出したのを見てから追う。この3つを、同じ項目（条件・例外）で比べられる。

## 3. 方式A（広く読む）と方式B（重要箇所を先に絞る）の比較

### 方法

- 方式B：読む前に規則を決め、その規則で選んだ節だけを読んだ。
  - 規則は、見出しに「理由・なぜ・条件・場合・NG・べき・判断・カウンター・兆候・いつ・使い分け・対策・why・when・checklist・back off」などを含む節と、結論（まとめ・終わりに）の節。
- 方式A：その後で残りの節も読み、方式Bで取れなかった判断の部品を数えた。
- 比較した4件で、読んだ文字数を数えた（空白を除く。本文の文字数）。

### 結果（実測）

| 資料 | 方式Bで読んだ文字数 / 全体 | 方式Bで取れた部品 / 方式Aで取れた部品 | 方式Bで落としたもの |
|---|---|---|---|
| 劣勢時5選（lol-guide）| 870 / 2,798（31%）| 2 / 5 | **最重要の「劣勢時はスキルでウェーブを処理せず自陣側に保つ」**。見出しは「『耐える』ためのレーン状況を作り出す」で、規則の語を含まなかった |
| ロームへの対処（lol-guide）| 2,040 / 2,792（73%）| 3 / 4 | ミッド中央へのワード（同じ著者の別記事にもある）|
| キーストーンの使い分け（lolgaren）| 544 / 2,692（20%）| 0 / 1 | 理由と例のすべて。見出しが「アクシャン対ダイアナ」のような対面の名前だけで、規則で選べない |
| トレードの基本（MetaBot）| 4,199 / 10,112（42%）| 2 / 4 | **例外と条件**：「敵ジャングラーが近いと普段のトレードも罠」（時間帯別の節）、「征服者の相手とは戦闘を長引かせない」（FAQ）|
| **計** | 7,653 / 18,394（42%）| **7 / 14** | |

- 方式Bは読む量を約4割に減らしたが、部品は半分しか取れなかった。
- 落としたものには、**最も重要な判断、条件、例外**が含まれていた。
- したがって、**方式Bで十分な品質を保てたとは結論づけない**。方式Bは将来の標準方式に採用しない。

### 方式Bが成り立つ条件・成り立たない条件

- 成り立ちやすい：見出しが問いや条件の形になっている記事。例：LoL Theory の「When to Use Each Wave State」、lol-guide の「追いかける条件」。
- 成り立たない：
  - 見出しが名詞や対面名だけの記事（lolgaren に多い）。
  - 条件・例外が FAQ・表・時間帯別の節にある記事（MetaBot）。
  - チャプターも説明欄の要約もない動画（Dopa の字幕動画）。方式Bを当てる手がかりがない。
- 方式Bで読む節を選ぶのは、Phase 5A の深さの推定と同じ問題を持つ。題名・見出しは、判断の理由がどこにあるかを十分には示さない。

### 1件あたりの作業をどれだけ減らせそうか

- 読む量は、4件の実測で約4割に減った。ただし部品の半分と重要な例外を失ったので、**方式Bだけを抽出方法にするのは不適切**。
- 現実的な使い方：方式Bを「最初に読む節の順番」に使い、見出しが名詞だけの記事や、FAQ・表がある記事は全体を読む。作業時間そのものは測っていないので、時間の削減量は示せない。

## 4. 重複と独自性

関係は29件の部品の間に36本を記録した。**関係の本数は、独立した根拠の数ではない**（下記）。

| 種類 | 本数 | 例 |
|---|---|---|
| 同じ原典の翻訳・再説明（same_source_restated）| 0 | 今回は該当なし（翻訳版は1件の原典としてだけ扱った）|
| 同じ著者の再説明（same_author_restated）| 6 | lol-guide の劣勢時5選とロームへの対処に、同じカウンターアクション・ワードの説明がある。根拠は1つと数える |
| 独立した著者が同じ結論（same_conclusion_independent）| 15 | 「迷ったら引いてファーム」（MetaBot・lol-guide）、「相手が主要スキルを使った直後が攻め時」（MetaBot・Dopa）、「劣勢なら自陣側でウェーブを保つ」（lol-guide・Dopa・Dignitas）|
| 結論は近いが、条件・理由が違う（condition_differs）| 11 | ロームを追う条件（lol-guide：視界と味方の優勢、LoL Theory：相手が踏み出したのを見てから、Dopa：TF の R がある）。フリーズで残すミニオンの数（2〜3体、3体以上、3〜4体多く）|
| 一般原則への具体的な例外（exception_of）| 2 | 「ミッドではフリーズが難しい」（LoL Theory）に対し、ウェーブを戻せないメレー（フィズ）が相手なら、ミッドでも自陣側に引く（Dopa）|
| 主張の対立（conflicts_with）| 1 | 「序盤のスロープッシュは避ける」（Dignitas 2019）と「序盤の1・2ウェーブをスロープッシュするチートリコール」（lol-guide 2026）。時代と対象が違い、どちらが現行で正しいかは未確認 |
| 補完（complements）| 1 | 「結果と判断を分けて振り返る」（Thinking in Bets）に対し、lol-guide は「追うべきだったかをリプレイで確認する」と具体的な場面を示す |

わかったこと：
- 同じ結論を1件にまとめると、**理由と成立条件の違い**が失われる。例：「自陣側に保つ」の理由は、lol-guide では劣勢、Dopa では対面の特性。
  - 結論が同じでも部品は別に残し、関係で結ぶのがよい。
- 「独立した著者が同じ結論」の15本は、両方向に記録したものを含むので、部品の組としては9組。さらに結論ごとにまとめると、独立した著者の裏付けがあるのは次の7つの結論だけ（各2〜3人）。

| 結論 | 独立した著者 |
|---|---|
| 劣勢・不利時はウェーブを自陣側に保つ | がりある、Dopa、Ahrivve（Dignitas）|
| 敵ジャングラーの位置が不明なら前に出ない・タワーを殴らない | がりある、MetaBot |
| 不利なら無理に戦わず引いてファームする | がりある（同じ記事の2部品）、MetaBot |
| フリーズには機会の代償がある | がりある、Griffin Wood |
| 相手が主要スキルを使った直後が攻め時 | Dopa、MetaBot |
| 戦闘の長さで判断（キーストーン・トレード）が変わる | 北川楓、MetaBot |
| 押し切ってからきれいにリコールする | 北川楓、Griffin Wood |

- 同じ著者の一致（6本）は、根拠として数えない。
- Dignitas の2記事（Ahrivve と Chillwang）は著者が違うが同じ媒体なので、1つの部品に並べて記録し、互いを独立した裏付けとは数えていない。
- 数値（残すミニオンの数）は資料ごとに違い、時代も違う。どれかに統一すると、確認していない値を正しいことにしてしまう。

## 5. 判断理由の検索（8問）

### 方法

- 資料の検索：アプリの `search()`（変更していない）。
- 判断の部品の検索：`tools/experiments/decision-units.js search`。質問から2文字以上の語を取り出し、部品の文（Topic の別名を含む）に現れる語の数で並べる、素朴な方式。
- 期待する部品は、質問ごとに人（AI）が決めた。

**注意（評価の偏り）**：判断の部品の「解決したい問題」などの文は、8問を見た後で AI が書いた。質問と同じ語（例：「分析」）が入りやすく、部品の検索に有利に働いた可能性がある。下の結果は、その偏りを含む。

### 結果

| 質問 | 資料の検索（上位）| 判断の部品の検索（期待した部品の順位）|
|---|---|---|
| なぜ不利な対面でウェーブを押してはいけないのか | 条件に一致3件、1位が劣勢時5選（該当する資料）| 中心の部品（自陣側に保つ）は26件中6位。3語一致で5件が同点 |
| 敵ジャングラーの位置が分からないとき、何を優先するべきか | 条件に一致0件、関連候補6件 | 「敵ジャングラーが近いと罠」2位、カウンターアクション4位（同点4件）、ワードは届かない |
| ロームを追わずに別の行動を選ぶ理由 | 条件に一致1件（スノーボールの記事）。ロームへの対処は4位 | 14件が「ローム」1語で同点。期待した部品は11〜12位 |
| フリーズが必ずしも最適ではない場面 | 「最適」が無視され、認識できた条件に一致1件 | 9件が「フリーズ」1語で同点。期待した部品は3位 |
| 火力よりも生存を優先する条件 | **0件**（「火力」「生存」が資料中にない）| 4件だけ。不利時のビルドの部品は2位、「迷ったら引く」は届かない |
| MIDでリコールのタイミングを決める理由 | 条件に一致3件（Dignitas、VeigarV2 の2本）| ミッドの4ウェーブ目の部品が1位 |
| プレイの失敗原因をどう分析するか | **0件** | 振り返りの部品が1位（ただし上の偏りの影響がありうる）|
| 同じ戦術が別のマッチアップでは通用しない理由 | 「戦術」「通用」が無視され、マッチアップの資料10件 | ブラッドミアの部品が1位、ブルーザーの部品が2位 |

### 語の一致の限界（誤一致・未到達）

- **否定が消える**：「追わず」「押してはいけない」「必ずしも〜ではない」は、ひらがなと1文字の漢字で区切られ、検索語に残らない（テストで確認）。
  - そのため「ロームを追わずに」は「ローム」1語になり、ロームを追う理由の部品と、追わない理由の部品を区別できない。
- **同点が多い**：1〜2語の一致で多くの部品が同点になり、順位は意味を持たない。
- **関係のない一致**：質問1で、TF 対フィズの「CD 中に攻める」部品が上位に入った。「不利」「対面」が Topic の別名（不利対面など）で一致しただけ。
- **言い換えに届かない**：「生存」は部品では「安定性」「体力を保つ」と書かれ、一致しない。「火力」は「ダメージ」。
- **方向・立場の違い**（Phase 5A の P04 と同じ問題）：「タワー手前」が敵タワーか自陣タワーかを区別できない。

### AI が判断の部品から回答した例（原典の主張と AI の推論を区別）

**質問1：なぜ不利な対面でウェーブを押してはいけないのか**
- 原典の主張（lol-guide 劣勢時5選「3.」）：劣勢時に序盤からスキルでウェーブを処理すると、相手にフリーズされ、ソロキルやガンクの圧力を受け続ける。ウェーブを自陣側に保てば、トレードを仕掛けやすく、相手のロームも牽制できる。
- 原典の主張（lol-guide ウェーブの勘違い「4.」）：処理が遅いのに中途半端に押すと、敵タワー手前でウェーブが止まり、相手にフリーズされる。
- 原典の主張（Dopa、1:17〜4:46）：TF 対フィズでは、ラストヒットだけでウェーブを自分側に引く。フィズはメレーでウェーブを戻せず、E を使えばガンクを受けるから。
- AI の推論：3つとも「押すと、相手に有利な位置でウェーブが止まる」点が共通している。ただし Dopa の例は対面の特性に依存する。「押さない」は劣勢時の原則で、劣勢でなく押し切れるなら、別の判断（リコールやロームのために速く押す。LoL Theory）になる。
- 未確認：現行パッチで成り立つかは、どの資料も検証していない。

**質問8：同じ戦術が別のマッチアップでは通用しない理由**
- 原典の主張（lolgaren リサンドラ対策）：リサンドラの Q は横に歩けば当たらず、得意距離は450。ブラッドミアは死神の残り火で、Q を当て続ける。
- 原典の主張（lolgaren アニビア）：死神の残り火は Q を当てにくい相手には弱く、アニビア相手なら征服者に劣る。
- 原典の主張（MetaBot）：短期戦のブルーザーには相手の得意な時間に戦わず、征服者の相手とは戦闘を長引かせない。
- AI の推論：同じキーストーンでも、相手の妨害と射程によって「自分のスキルを当て続けられるか」「戦闘がどれくらい続くか」が変わり、評価が逆になる。この一般化は AI の整理で、原典がそう述べているわけではない。

### 評価

- 判断の部品は、資料単位の検索では届かない質問（質問5・7）に一部届き、答えの根拠となる節（所在）を返せる。
- しかし、語の一致だけでは、否定・条件・立場の違いを扱えず、同点も多い。**判断理由の検索は「部品として記録すれば語の一致で成立する」とは言えない**。
- 必要なのは、質問の意図（否定、何と何の比較か、誰の立場か）を読み、部品の「観測できる状況」「成立条件」「例外」と照合する段階。AI 推論の段階で扱う課題として残す（今回は実装しない）。

## 6. 品質評価のまとめ

| 観点 | 評価 |
|---|---|
| 単なる要約より役立つか | 役立つ。状況・理由・条件・例外に分かれ、別の資料と比べられる |
