## 記号

- **種類**
  - 仕様＝Wiki・公式で確認できる記述

  - 旧仕様＝過去のパッチの仕様
  - AI＝仕様の記述からの AI の推論（戦術・計算）
  - 仮説＝確かめる手段がまだない推論
  - 原典の著者の主張は、今回は集めていない。攻略記事は読んでいないので、勝ち筋・対策の連鎖はすべて AI の推論になる
- **視点**：使＝使う側／対＝対策する側／両＝両方から参照する仕様
- **ゲーム内での検証**：すべて未実施。
- Wiki の記述は、下の版（revid）の時点のもの。注記に「バグ」とある挙動は、修正されうるので仕様と区別する。
- 原典の文章は写さず、要旨を日本語で書いた。取得した原文の一時コピーは、記録後に削除した。

### Topic の不足の程度

- **チャンピオン**：Topic は3件（champ-veigar・champ-twisted-fate・champ-jax）だけ。4体とも Topic がない。
  - 散策・Topic での絞り込みでは、チャンピオンごとの入口がないので、**問題は大きい**。
  - 検索では、ノートの照合が本文の語を使うので、「ゼド」「サッシュ」などの語で届く（A の実装）。問題は小さい。
- **ロール**：role-mid だけ。ラックスのサポート（LX15）、モルデカイザーのトップを表せない。ロール共通の散策・検索で偏りの原因になる。
- **アイテム・CC の種類**：itemization・crowd-control はあるが、個別の効果（浄化・スペルシールド・ステイシス）の Topic はない。ノートの数が少ないうちは、本文の語の照合で足りる。
- **マッチアップ**：matchup が1件ある。「誰と誰の対面か」は表せないが、2体のチャンピオンの Topic を両方付ければ表せる（新しい形は不要）。
- 結論：**最小限の追加はチャンピオンの Topic（4件）とロールの Topic**。既存の形（チャンピオンは concept、ロールは category）で足りる。ただし、チャンピオン Topic の親の置き方は未定（既存の2件で異なる）。

### 既存モデルだけで表す最小限の方法（次の開発候補）

新しい関係の種類を使わずに、今の形だけで表す方法。

1. **チャンピオン Topic**：既存の champ-jax・champ-veigar と同じ形（kind: concept）で、champ-malzahar・champ-mordekaiser・champ-zed・champ-lux を追加する。
   - 注意：既存のチャンピオン Topic の親はそろっていない（champ-jax は aa-negation、champ-veigar は cat-expert）。チャンピオン用の大分類はないので、大分類を1つ置くか、既存の分類の下に付けるかを先に決める必要がある。
   - ロールは role-mid（kind: category）と同じ形で、必要なロール（例：サポート・トップ）を足す。
   - マッチアップのノートには、2体のチャンピオン Topic と matchup を付ける。
2. **仕様を共有する**：スキルの仕様は1ノート（source_stated・mechanic）にまとめ、そのチャンピオンの Topic だけを付ける。例：MZ19「サプレッションが外れてもテザーが続く」。
3. **使う側・対策側**：応用のノートを別々に作り、どちらも仕様のノートに `reason_for`（仕様 → 応用）でつなぐ。例：MZ19 → MZ10（使う側）、MZ19 → MZ22（対策側）。視点は statement の書き出し（「使う側：」「対策：」）で示す。
4. **対策 → 再対応**：今は `context_of` でつなぎ、notes_ja に「MZ9 への再対応」と書く。向きの意味は失われるが、表示とリンクはできる。
5. **旧対策**：`historical`（valid_until・superseded）で表す。例：MK8。現行の対策のノート（MK12）と `context_of` でつなぐ。

この方法の限界：視点と「対策」の向きが、データの項目ではなく文章に頼る。これを項目にする必要が出たら、下の拡張の候補を検討する。

### 最小限の拡張の候補（提案のみ。今回は実装していない）

1. 関係の種類に `counters`（対策する）と `responds_to`（再対応する）を加える。Relation の type は文字列で、検証は種類を制限していない。必要なのは、画面の表示名（NotePage の RELATION_LABELS）の追加だけ。
2. 視点は新しい項目を作らず、Topic（matchup）と関係の向きで表す。例：対策のノート `counters` 勝ち筋のノート。
3. 正式資料：Wiki のチャンピオン4件（スキルのデータのページ）、Wiki のアイテム・CC の定義、Riot のパッチ14.8、Data Dragon を登録すれば、仕様・公式の75件（旧仕様2件を含めると77件）に根拠を付けられる。
