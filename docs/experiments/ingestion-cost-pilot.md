## 2. 各工程の作業量

**計測方法と限界**
- 操作回数は、実際のツール呼び出しを数えた。
- 経過秒数は、各工程の前後に記録した時刻の差。ツールの実行時間と、その間の AI の応答時間の両方を含み、人の作業時間ではない。
- トークン消費は未計測（この環境では取得できない）。
- 記事の取得は WebFetch で行った。これは、小型モデルがページを読んで答える仕組みで、本文そのものは受け取っていない。「読んだ範囲」は、質問で指定した範囲のこと。
- WebFetch の呼び出し回数は、工程の数と一致しない。1回の呼び出しで複数の工程の情報を得たり（B の工程1で工程2の候補も選んだ）、1つの工程で呼び出しがなかったりする（工程2・4）。

## 9. 計測の限界

- 経過秒数は、ツールの呼び出しの間隔で、人の作業時間ではない。工程6（要約）は、レポートの作成と区別できず、未計測。
- トークン消費は、3資料とも未計測。
- A の所要時間は、パイロットのときに記録していないため未計測（推定していない）。
- B・C の読み取りは WebFetch（小型モデルによる要約・判定）で、本文そのものを読んでいない。判定の誤りの可能性は残る。
- 資料は3件だけで、傾向を一般化できるほどの数ではない。

## 10. 照合チェック手順（次回から使う）

判断候補1件ごとに、次の表を埋める。根拠の原典 URL と該当箇所（見出し・時刻）は必ず書く。原文を確認できない場合は、推測で SUPPORTED にせず UNVERIFIABLE とする。

**抽出のとき（最初から書く）**

```
候補：（判断候補の要約1文）
対象：ロール／チャンピオン／対面／時間帯（原典で特定できる範囲だけ。書かれていなければ「記載なし」）
観測条件：
判断・行動：
理由：
例外・代償：（同じ節だけでなく、ほかの節・時刻も見る）
原典：（URL）／該当箇所：（見出し・節・時刻）
パッチ依存性・未確認事項：
確認の方法：原文を直接確認 ／ WebFetch など別モデルの要約で確認 ／ 字幕 ／ 映像
```

**照合のとき**

```
| 主張の文 | 原典の該当箇所 | 判定 | 根拠の語句（15字・15語以内）|
|---|---|---|---|
| … | … | SUPPORTED / PARTLY / NOT SUPPORTED / UNVERIFIABLE | … |

チェック：
[ ] 表現の強さが原典と同じ（原典より強くしていない：勧める／条件付きで許す／可能性の表現。原典より弱くもしていない）
[ ] 成立条件と、実戦の一例（チャンピオン・場面）を混同していない
[ ] 「対象」の範囲を超えて一般化していない
[ ] 別の節・時刻に、例外・代償・反対の条件がない（ある場合は書き足す）
[ ] すべての判定に、該当箇所と根拠の語句がある（根拠がなければ UNVERIFIABLE）
[ ] NOT SUPPORTED の部分を主張に残していない（削るか、原典にある内容に置き換える）
```

- PARTLY・UNVERIFIABLE が1つでもあれば、その文は直すか、未確認事項に移す。
- WebFetch など別モデルの判定で SUPPORTED になっても、「原文を直接確認した」とは書かない。
- 初回の実験の結果は `docs/experiments/verification-check-pilot.md`（対象・未確認事項の欄は、この実験の結果を受けて抽出の書式に移した）。
