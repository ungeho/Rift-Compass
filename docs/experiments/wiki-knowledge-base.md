# 英語 LoL Wiki の網羅的な収録と、ロール・スキルの表示（2026-11-02）

方針：英語の League of Legends Wiki を、スキルの数値だけでなく、ゲームプレイの基礎情報を可能な限り網羅して収める主要な知識源として扱う。情報量の多さは対象を絞る理由にしない。取得済み・構造化済み・表示可能・検証済みを分けて数える。

## 1. 取得の条件

| 項目 | 確認した内容（2026-11-02） | 対応 |
|---|---|---|
| ライセンス | 本文は CC BY-SA 3.0（Wiki の siteinfo）。画像は本文と同じとは限らない（Weird Gloop の Licensing） | 各ファイルに license（出典の表示・同じライセンス）を記録。画像は取得しない |
| robots.txt | `/*api.php` を不許可（Special: なども不許可） | **api.php は使わない**。ページの raw（`/en-us/<ページ>?action=raw`）を、説明的な User-Agent・1.1秒の間隔・キャッシュで取得 |
| 版 | raw は revid を返さない | `Last-Modified`（版の時刻）・取得日時・URL を記録。revid は記録できない |
| 記事の本文 | 大量の再配布は避ける | 記事は見出し・テンプレートの数・リンクの数だけ。データのテンプレート・モジュールは値をそのまま保存（出典つき） |

- 以前の作業（〜2026-11-01）は api.php で Wiki を取得していた。robots.txt の記載を今回確認したので、以後は raw に切り替えた。過去の取得で記録した revid（Module:ChampionData 4088335 など）はそのまま残す。
- 429・5xx は回避せず、30秒待って1回だけやり直し、だめなら失敗として記録する（今回は0件）。

## 2. 方式

- `npm run wiki -- harvest [--only 分野,...]`（`tools/gamedata/wiki-ingest.js`、解析は `tools/gamedata/wiki.js`、依存なし）。
- 対象のページは Wiki 自身のデータと公式 Data Dragon から見つける：スキル＝Module:ChampionData の技名 → `Template:Data <チャンピオン>/<技>`、アイテム＝`Module:ItemData/data/index` → `Module:ItemData/data/<アイテム>`、ルーン＝Data Dragon の runesReforged → `Template:Rune data <ルーン>`。
- 転送（#REDIRECT）は転送先を記録し、転送先が一覧にないときは転送先も取得する（Nunu & Willump → Template:Data Nunu/…）。
- 出力：`public/gamedata/wiki/<取得日>/`（abilities/<キー>.json・items.json・runes.json・modules/・units.json・articles.json・coverage.json）。画面は開いたチャンピオンの1ファイルだけを読む。`manifest.json` の `current.wiki_snapshot` が画面の読む取得日。
- 再実行はキャッシュから組み立て直し、同じページを取り直さない（今回の解析の改善は、すべてキャッシュから再構築した。追加の取得は転送先の9件・ルーン1件・ロールクエストのページだけ）。
- 原情報（params の文字列、Lua の値）と、道具が解釈した値（parsed・leveling・ratios）を分けて保存する。解釈できないものは unparsed に項目名と理由を残す。

### 解析の内容

- データのテンプレート：`{{#vardefine:名前|値}}`・`{{#var:名前}}`・`{{#expr:式}}`（数だけの四則演算）を置き換えてから、`{{{{{1<noinclude>|Ability data</noinclude>}}}|…` の本体の引数を読む。
- 値：数、`a / b / c`、`{{ap|a|b|c}}`、`{{ap|a to b}}`（ランク数で線形補間。ランク数は Data Dragon の maxrank、パッシブは補間しない）、`{{ap|100*0.35 to 140*0.35}}`（数式）、`{{ap|90/100*(25 to 55)}}`（式の中の範囲が1つなら補間）、`{{fd|x}}`。表示用の記法（`{{tip|…}}`・`{{tt|値|説明}}`）だけを除けば数になるものは `simplified` の印を付けて読む。
- leveling：`{{st|ラベル|値}}` ごとに、基礎値（ランク別）・係数（`(+ 60% AP)`、ランク別の係数）・割合の基礎値の単位と対象（`8〜10% of target's missing health`）。
- Lua：`local` の定数の参照、長い文字列 `[=[…]=]`、長いコメント `--[=[…]=]`、数式（`84+1000/17`、元の式は `__expr` に残す）。

## 4. ロール（ポジション）

### チャンピオンへの導線（A）

- `public/gamedata/wiki-championdata/4088335/positions.json`：Wiki の Module:ChampionData（revid 4088335）の client_positions（Riot クライアントの推奨）と external_positions（統計サイトなどでの使用）から、ポジション → チャンピオンの一覧を作る（`npm run gamedata -- positions`）。同じチャンピオンを複数のポジションに入れ（フレックス）、データは複製しない（Topic ID と一覧の参照だけ）。
- 推奨の数：トップ 49・ジャングル 45・ミッド 45・ボット 29・サポート 36。推奨にない統計サイトでの使用はトップ 12・ジャングル 8・ミッド 13・ボット 1・サポート 12。**推奨だけで全173チャンピオンに届く**。
- Topic の親子は変えない（チャンピオンはロールの子にしない）。ポジションのページは一覧を読んで表示する。「チャンピオン別」は全件の一覧として残す。

### ポジションのページで見つかるもの（B）

- このポジションのチャンピオン（推奨／統計サイトでの使用を分ける、出典の revid つき）。
- このポジションで重要な Topic（**編集上の案内**。資料の分類による所属ではない）：トップ＝マッチアップ・トレード・ウェーブ管理・フリーズ・タワーダイブ・レーン主導権・劣勢時の戦い方 など。
- このポジション向けの判断材料（対象ロールにそのポジションを明記したもの。ロール共通は含めない）。
- ポジション名を含む資料（題名・紹介文の語の一致。そのポジションの解説とは限らない）。
- 知識ノート：ロールクエストのノート（ポジションの Topic と、新しい Topic「ロールクエスト」）。

## 6. 基礎データからの推論（F）

- 「式から導ける性質」は、係数・割合の対象から機械的に判定する数学的な性質だけ（`src/gamedata/wikiAbility.ts` の derivedProperties）：対象の最大体力・減少体力・現在体力に比例、自分の減少体力・増加体力、増加攻撃力、合計攻撃力、AP、防御のステータス。画面では「自動で判定・ゲーム内では未検証・戦術的な結論ではない」と明記。
- 「タンクに強い」などの戦術的な推論は、物理防御・魔法防御・軽減・CD・対象ごとの上限などの条件が要るので、今回は作らない。作る場合は tactical_inference の知識ノートとして、前提・成立条件・根拠（どの式から）を残す（既存の形式）。
