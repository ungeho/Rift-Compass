## 2. 方式

| 方式 | 手順 |

## 5. 方式Bの採否

**今回の定義の方式Bは、不採用とする。**

| 観点 | 結果 |
|---|---|
| 有用な知識を十分に発見できるか | 発見できた。方式Aだけが見つけた13件は、中11・低2 |
| 判断を逆転させる重要な例外を見落とさないか | 見落としは0件。ただし、記事5件では方式Bが全文の92〜100%を表示しており、実質的に全文を読んでいた。見落としが少ないのは、方式Bが効率的だったからではない |
| 誤った一般化を増やさないか | 増やしていない。冒頭が切れて理由が読めなかった文は、方式Bの記録で「途中で切れて未確認」とした |
| 作業量の削減が明確か | **明確でない**。記事では0.92〜1.18倍で、2件は方式Aより多く読んだ。動画1本だけ0.60倍 |
| 著者や資料形式の違いに対応できるか | **できない**。日本語の短い段落や1文ごとの改行の記事では、冒頭60字の表示がほぼ全文になる。動画は字幕が取れるかどうかが資料ごとに違い、1本は取れなかった |

- 不採用の主な理由は、作業量が減らないこと。短い段落の日本語の記事では、段落の冒頭を読むこと自体がほぼ全文を読むことになり、詳読と例外の確認が重なる分、かえって増える。
- 長い文章（英語の字幕、1万字級の記事）では削減の余地があるが、今回は動画1本だけで、**形式別の方式Bは未判定**とする。この1本では、MID を優先した区間の選び方で、トップ固有の判断（中）をまとめて落とした。
- 今の段階では、記事は全文を読む（方式A）のが妥当。コストの大部分は読むことそのものより、字幕の取得（動画）と抽出の判断にある。

## 6. 次に試す価値があるもの（今回は実装していない）

- 文字数の目安で読み方を分ける：たとえば5,000字以下の記事は全文を読み、それより長い資料だけを選択的に読む。今回の記事は2,464〜4,291字で、どれも全文を読むほうが安かった。
- 動画は、字幕が取れるかを先に確かめ、取れない資料は早めに外す（今回の s6 は、3つの方法を試すのに時間を使った）。
- 選択的に読む区間を選ぶとき、対象ロールの優先が、他ロールの判断をまとめて落とす（s5）。落とした区間を記録しておく。
